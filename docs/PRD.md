## 1. 产品概述

### 1.1 产品定位
面向金融/银行行业内部团队的**测试用例全生命周期管理平台**，覆盖从需求分析、用例设计、评审、执行到缺陷跟踪的完整测试流程。

### 1.2 目标用户
- **测试经理**：创建测试计划、分配任务、查看统计报告
- **测试工程师**：编写用例、执行测试、提交缺陷
- **项目经理**：查看项目进度、测试覆盖率
- **系统管理员**：用户管理、权限配置、系统设置

### 1.3 核心价值
- 统一测试资产管理，避免 Excel 分散管理
- 支持 SIT/UAT/PRE 多阶段灵活推进
- 缺陷与用例关联，追溯测试覆盖
- 自动化集成，支持 CI/CD 流水线

## 2. 功能需求

#### 2.1.1 登录/登出

#### 2.1.3 个人信息
- 修改密码（原密码验证）
- 编辑个人资料（显示名称、邮箱、手机号）

### 2.2 项目管理

#### 2.2.1 项目信息
- 项目名称、编号、描述
- 项目等级、类型
- 测试经理、技术经理、SA
- 是否重点项目、启动状态
- 星标关注功能

#### 2.2.2 项目权限
- 成员只能看到分配给自己的项目
- 项目内角色动态定义（管理员可创建/编辑角色）
- 默认系统角色：项目经理、测试负责人、测试员、只读用户

#### 2.2.3 项目模板
- 模板打包内容：阶段天数（SIT/UAT/PRE）、准入/准出门禁规则、自定义字段、标签、数据字典项目级项
- 创建项目时选择模板：不选则套用「默认模板」，选择「不套用」则完全不继承任何配置（接口以 `template_id=0` 表达）
- 项目单独调整的阶段天数优先于模板；未调整（留空）的沿用模板值
- 套用为幂等：同一条门禁规则、同名字段、同名标签、同字典项重复套用会被跳过，不会堆叠重复配置
- 另存为模板：可从已有项目反向采集上述配置生成模板草稿，确认后再保存
- 编辑项目时修改模板选择只更新「来源记录」，不会重新套用或回滚已生效的配置
- 被项目引用的模板不可删除（提示先解除引用）；默认模板删除后自动顺延首个模板为默认，保证新建项目有默认来源
- 权限：模板的增删改与套用仅管理员可执行，全部写入操作日志
- 前端入口：系统管理 → 项目模板；新建/编辑项目对话框内的「项目模板」下拉

### 2.4 测试计划与执行

#### 2.4.1 测试计划
- 关联项目、版本号
- 三阶段时间规划（SIT/UAT/PRE）
- 阶段默认天数可配置
- 删除计划时级联清除其执行记录、逐步结果、轮次与报告；关联缺陷改为不指定计划，
  不留悬挂引用（保证统计与审计数据可归属）

#### 2.4.2 阶段推进（灵活模式）
- **顺序推进**：SIT → UAT → PRE
- **跳跃推进**：可直接从 SIT 跳到 UAT 或 PRE
- **回退限制**：只能向前推进，不能回退
- 不强制要求 100% 通过才能推进，但需通过项目配置的阶段门禁（见 2.4.6）
- 计划可在当前阶段标记完成；误操作可重新打开，两者均写入操作日志

#### 2.4.3 测试执行
- 单条用例执行记录（通过/失败/阻塞）
- 执行备注、截图上传
- 执行历史记录（含所属测试环境）
- 执行时可指定测试环境，用于区分同一用例在不同环境上的结果

#### 2.4.4 测试轮次
- 计划下创建多个执行轮次
- 轮次独立统计
- 轮次完成标记

#### 2.4.5 批量执行
- 选择多条用例批量标记状态
- 批量分配执行人员

#### 2.4.6 阶段准入/准出门禁
- 按项目 × 阶段（SIT/UAT/PRE）× 类型（准入/准出）配置阈值规则，可逐条启停
- 校验时机：推进阶段 = 当前阶段准出 + 目标阶段准入；标记完成 = 当前阶段准出
- 规则项（9 类，阈值可调）：纳入用例数、执行率、通过率、失败数、阻塞数、未执行数、
  评审通过率、未关闭缺陷数、未关闭紧急缺陷数（紧急口径见 2.11.4）
- 指标口径与计划进度、测试报告一致：以计划圈选范围为分母，取该阶段每条用例最近一次执行结果
- 未配置规则表示不限制；未达标时阻断操作并列出「要求 / 实际」明细
- 越权通道：仅管理员可强制推进或强制完成，且必须填写理由；操作日志记录未达标明细与理由
- 前端入口：功能测试管理 → 阶段门禁（配置）；项目批次 → 阶段推进对话框（展示校验结果）

#### 2.4.7 测试环境管理
- 环境按项目维护，属性包含名称、主要阶段（SIT/UAT/PRE）、状态、访问地址、部署版本、负责人、备注
- 状态四值：可用 / 占用中 / 维护中 / 已停用；同一项目内环境名称唯一
- 执行结果可归属环境：手工执行、项目批次批量执行、自动化结果回写、JUnit XML 导入四条入口均支持
- 环境校验：不存在、跨项目、已停用的环境不允许写入执行记录，接口返回明确原因
- 环境维度反查：环境列表展示执行数与失败/阻塞数，可下钻查看该环境全部执行记录（用例、批次、阶段、结果、时间）
- 追溯保护：已被执行记录引用的环境不能删除，只能停用，删除请求被拒绝并提示改用停用，避免执行链断裂
- 权限沿用项目成员体系：非成员读写均拒绝；新增、编辑、停用/删除、执行均写入操作日志，执行日志附带环境名
- 前端入口：功能测试管理 → 测试环境（列表筛选按项目/阶段/状态自动刷新）；用例执行对话框、批量执行对话框、自动化集成表单提供环境选择

### 2.5 缺陷管理

#### 2.5.1 缺陷属性
| 字段 | 说明 |
|------|------|
| 标题 | 缺陷描述 |
| 严重程度 | 内置默认 致命/严重/一般/提示，取值与「计入紧急」标记由数据字典配置（见 2.11.4） |
| 优先级 | 内置默认 P0/P1/P2/P3，取值与「计入紧急」标记由数据字典配置 |
| 状态 | 新建/处理中/已修复/已验证/关闭/重新打开 |
| 关联用例 | 可选关联测试用例 |
| 关联计划 | 可选关联测试计划 |
| 提交人 | 自动记录 |
| 指派人 | 可分配处理人 |

#### 2.5.2 缺陷流转
- 状态机后端强制校验,非法跳转返回 400 并提示可选状态:

| 当前状态 | 允许流转到 |
|----------|------------|
| 新建 | 处理中、关闭 |
| 处理中 | 已修复、关闭 |
| 已修复 | 已验证、重新打开 |
| 已验证 | 关闭、重新打开 |
| 关闭 | 重新打开 |
| 重新打开 | 处理中、已修复、关闭 |

- 修复后必须由提单人验证才能关闭,避免"开发自关闭"
- `admin` 可强制流转(误操作纠正);普通成员仅可见合法目标,前端「流转」下拉按当前状态动态渲染
- 进入 `已修复`/`关闭` 分别记录 `resolved_at`/`closed_at`;`重新打开` 或退回 `处理中` 时清空这两个时间
- 流转通知: 已修复提醒提单人验证,重新打开提醒处理人;严重程度或优先级命中字典「计入紧急」标记的额外推送群机器人
- 缺陷与用例双向关联

#### 2.5.3 缺陷附件
- 支持上传日志、截图、文档、压缩包作为缺陷证据,单文件 20MB 上限,扩展名白名单校验
- 附件列表显示文件名、大小、上传人、上传时间;图片支持点击放大预览
- 下载按 RFC 5987 还原中文文件名;存储文件名重写为 UUID,不泄漏原始名
- 仅上传者本人或管理员可删除(后端返回 `can_delete`),删除时同步清理磁盘文件
- 删除缺陷时级联删除其全部附件记录与磁盘文件,不产生孤儿文件

### 2.10 系统集成

#### 2.10.1 自动化集成
- 自动化测试指南
- 批量执行接口（JSON 回写）
- 结果回传接口
- JUnit XML 结果导入

**JUnit XML 导入**：CI（JUnit / pytest / Jest / Robot Framework 等产出的
`results.xml`）可直接上传，无需二次开发脚本。

- 状态映射：`failure`/`error` → 失败，`skipped` → 阻塞，无子节点 → 通过；
  `time` 属性四舍五入为执行耗时（秒）。
- 用例匹配：先按用例标题（忽略大小写）精确匹配，再按名称中的编号
  `TC-1024` / `case_1024` / `#1024` 匹配用例 ID；两者都落空则列入未匹配清单并给出原因。
- 范围校验：匹配到的用例仍需在计划的用例范围内，范围外不写入执行记录。
- 预览模式：只解析与匹配，返回套件统计和未匹配明细，不落库；用于首次接入时校准命名。
- 每次导入都新增执行记录（保留历史，支持 Rerun），并同步用例当前状态；
  框架名与构建号写入备注，便于追溯来源批次。
- 限制：单次最多 20 个文件、单个不超过 10MB、解析用例不超过 2000 条；
  非 UTF-8 文件按 GBK 回退解析，损坏文件单独报告错误而不影响其余文件。
- 计划删除时其执行记录一并清除，不会残留无法归属的结果。

- 构建触发测试

#### 2.10.3 外部工具

### 2.11 系统管理

#### 2.11.1 用户管理
- 用户列表、启用/禁用
- 角色分配
- 密码重置

#### 2.11.2 操作日志
- 记录所有关键操作（登录、创建、编辑、删除、执行等）
- 支持按操作类型、用户名筛选
- 操作时间、IP 地址记录
- 日志只增不改不删：平台不提供修改与删除接口（防篡改要求见 2.11.5）

#### 2.11.3 系统配置
- 登录超时时间
- 密码有效期
- 阶段默认天数
- Nacos 配置中心集成（可选）

#### 2.11.4 数据字典
- 可配置类型：用例优先级、用例模块、缺陷严重程度、缺陷优先级、需求优先级；新增类型不改代码不可行，类型本身由系统定义，取值可配置
- 取值支持：新增、改名、排序、配色、启用/停用、标记「计入紧急」
- 作用域分层：全局项（`project_id` 为空）+ 项目级覆盖项；项目级同名项覆盖全局，项目级停用则隐藏该内置项，其他项目的自定义项不会串味
- 校验模式：`validate` 类型的写入值必须在启用项内，非法值接口返回 400 并列出可选值；`suggest` 类型（如用例模块）允许自由输入
- 历史数据兼容：编辑老数据时保留其原值作为可选口径（不因字典变更被拒），新建与批量导入严格按字典校验
- 字典驱动的业务口径：缺陷列表/详情的紧急标记、门禁的「未关闭紧急缺陷」、通知的群机器人广播、看板的「最高优先级用例」统计，均取自字典而非代码常量
- 固定不可配的类型（状态机键）：阶段、执行结果、评审状态、缺陷状态；接口只读并说明原因，避免改坏流转
- 前端入口：系统管理 → 数据字典（类型切换 + 全局/项目页签，筛选变更后自动刷新）；用例/缺陷/需求表单的下拉从字典读取并带 60 秒缓存

#### 2.11.5 审计日志防篡改
- 每条日志写入时计算哈希并与前一条串成哈希链；链头单独存放，写入靠链头行锁串行化，并发不会产生裂链
- 参与哈希的字段：日志 id、用户名、操作类型、操作对象、详情、IP、时间；不含 `user_id`（删除用户会级联置空，属正常行为）
- 哈希盐取自独立审计密钥（未配置时回退 JWT 签名密钥，界面明确提示）；只拿到数据库写权限、不知道盐的人无法整链重算
- 校验能力：整链校验、按区间分段校验、留痕校验（把「谁在什么时候查过」也写进链）
- 可识别四类问题：内容被篡改、链断裂（记录被删除/插入/重排）、未入链（绕过正常写入插入的记录）、链头不符
- 日锚定：按自然日聚合出单个锚定哈希，可抄录到工单或周报用于对外存证，次日比对即可确认当天日志未动
- 历史日志在启动迁移时自动回填哈希，仅保证回填之后的可验证性
- 权限：仅管理员可查看链状态、执行校验与生成锚定值；日志本身不允许通过接口修改或删除
- 前端入口：后台管理 → 操作日志（顶部完整性面板：链概况、校验按钮、异常明细表、日锚定；列表增加链上哈希列）

### 2.13 数据血缘与影响分析

#### 2.13.1 血缘关系图
- 覆盖六类对象：需求、用例、批次、执行记录、缺陷、测试环境；关系直接取自现有业务表，不新建血缘表、不需要额外维护，业务数据一变图即变
- 关系方向即业务流向：需求 →(覆盖) 用例 →(执行) 执行记录 →(产生) 缺陷；批次 →(圈选) 用例、执行记录 →(归属) 批次、执行记录 →(运行于) 环境、用例/批次 →(关联) 缺陷
- 两种视图：全景图（不选起点，铺开项目全部对象）与起点展开（任选一个对象为根，按 1-5 层向外扩散）
- 起点支持按类型 + 关键字检索（需求按标题/编号，用例按标题/模块，缺陷按标题）
- 规模可控：节点上限 10-2000 可调，超限按层次截断并明确提示；只返回已展示节点之间的关系，不留悬空连线
- 全景图对六类对象全部播种，孤儿对象（无需求关联的用例、无来源的缺陷等）也会出现在图上，不被静默隐藏
- 跨项目隔离：不属于当前项目或无权限的对象不出现在图中
- 点击图中节点即可直接对该对象做影响分析（执行记录只读，提示改从用例或批次入手）
- 前端入口：功能测试管理 → 数据血缘

#### 2.13.2 变更影响分析
- 回答「改/删这个对象会牵连什么」，支持需求、用例、批次、缺陷、环境五类对象（执行记录不可变更，故不提供）
- 区分「如果修改它」与「如果删除它」两种口径，各自给出处置建议
- 输出风险等级（高/中/低）与判定理由，例如「存在未关闭的紧急缺陷，且进行中批次依赖该用例」
- 影响面按对象分节展示：关联需求、受影响批次（含进行中批次）、执行记录、关联缺陷、历史版本、环境占用等，每节给出条数、状态说明与可跳转的深链
- 口径与门禁一致：紧急缺陷的「紧急」由数据字典的严重程度取值决定；未关闭 = 状态 ≠ 关闭；批次统计分母遵循圈选范围，未圈选范围的批次按项目全部用例计入并标注「隐式覆盖」
- 汇总结论直接指出是否卡住阶段准出门禁，便于评审时引用
- 只读能力：血缘与影响分析接口不写业务数据、不产生操作日志

#### 2.13.3 血缘体检
- 项目级一键体检，给出需求覆盖率、用例关联需求率、孤儿缺陷数
- 自动识别五类断链：未被任何用例覆盖的需求、未关联需求的用例、无来源的孤儿缺陷、未圈选范围的批次、无执行记录的用例
- 每类问题给出级别（正常/提示/断链）与说明，作为质量例会的问题清单

## 6. 术语表

|------|------|
| SIT | 系统集成测试 (System Integration Testing) |
| UAT | 用户验收测试 (User Acceptance Testing) |
| PRE | 预发布环境测试 (Pre-production Testing) |
| 用例 | 测试用例 (Test Case) |
| 缺陷 | Bug/Defect |
| 轮次 | 测试执行轮次 (Test Round) |
| 覆盖率 | 需求被用例覆盖的比例 |
| 准入/准出门禁 | 阶段进入/退出必须达到的量化阈值（Gate） |
| 测试环境 | 项目下登记的被测系统部署实例，执行结果可归属到具体环境 |
| 数据字典 | 优先级、模块、严重程度等枚举取值的可配置项，替代代码里的硬编码常量 |
| 计入紧急 | 字典项上的标记，决定哪些严重程度/优先级算紧急（影响门禁、通知广播、列表标记） |
| 项目模板 | 阶段天数、门禁、自定义字段、标签、字典项的打包配置，新建项目时套用 |
| 审计哈希链 | 操作日志逐条串接的哈希，用于证明日志未被改动、删除或伪造 |
| 链头 | 最后一条日志的哈希与计数，单独存放并用于串行化写入 |
| 日锚定值 | 某一自然日全部日志哈希聚合出的单值，用于对外存证与次日比对 |
| 数据血缘 | 需求、用例、批次、执行记录、缺陷、环境六类对象之间的关联关系图，取自业务表实时计算 |
| 影响分析 | 针对某个对象回答「修改/删除它会牵连哪些对象」，含风险等级、门禁结论与处置建议 |
| 血缘体检 | 项目级追溯完整性检查，列出未覆盖需求、未关联用例、孤儿缺陷等断链问题 |
| 隐式覆盖 | 批次未圈选用例范围时，按项目全部用例计入统计的口径 |

### 7.3 缺陷严重程度
内置默认值，实际取值以数据字典（2.11.4）为准；「计入紧急」标记决定门禁与广播口径，默认致命/严重为紧急。

| 严重程度 | 说明 |
|---------|------|
| 致命 | 系统崩溃、数据丢失 |
| 严重 | 主要功能不可用 |
| 一般 | 次要功能异常（接口未显式传严重程度时的默认值） |
| 提示 | 界面/体验问题 |
